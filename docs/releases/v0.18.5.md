# dbt-plan v0.18.5 — fewer false warnings, conservative safety checks

Two false-warning paths found while applying dbt-plan to external projects are
fixed in this patch.

## Unchanged dbt 1.12 snapshots

The whitespace-normalized file checksum used by dbt 1.12 no longer makes an
unchanged SQL snapshot look stale. dbt-plan additionally matches every snapshot
block by name and compares its body byte for byte. This detects meaningful edits
to spaces inside SQL strings or newlines after line comments, even when the
normalized checksum stays the same. Missing evidence, changed block membership
and unsupported outer templates still require review. Snapshot definition changes
remain warnings; snapshot DDL is not predicted. Closes [#314](https://github.com/PresentJay/dbt-plan/issues/314).

## SQL comments and cascade findings

A `ref()` inside disabled SQL can create a manifest dependency without an actual
read. Cascade analysis now excludes an edge only when fresh compiled SQL proves
the physical relation occurs in a comment and is absent from a readable query.
Original dbt graph selection and alternate real dependency paths are preserved.
Closes [#316](https://github.com/PresentJay/dbt-plan/issues/316).

Actual reads, explicit `depends_on`, executable MySQL/MariaDB comments, unknown
functions/relations, hooks, Python/ephemeral/custom models and unverified
compilation keep conservative dependencies. This does not resolve every false
warning or certify runtime safety.

## Upgrade and validation

```bash
pip install --upgrade dbt-plan==0.18.5
# Optional MCP server:
pip install --upgrade 'dbt-plan[mcp]==0.18.5'
```

Local fixture validation in Ddscully's public dlt/dbt project removed two false
snapshot warnings on unchanged input. A contracted column addition still warned
before dbt failed on the existing incremental target; an isolated copy with that
target absent built successfully.

Replay of NBA's original compiled manifests reduced uncertainty findings from
15 to 11 while retaining six broken-reference findings and two data-test failures.
These are local compatibility checks, not accepted integrations or confirmed
adoption. Release artifacts are rechecked after publication.

The executable-comment guard follows the documented
[MySQL](https://dev.mysql.com/doc/refman/8.4/en/comments.html) and
[MariaDB](https://mariadb.com/docs/server/reference/sql-statements/comment-syntax)
semantics; it conservatively keeps these dependencies instead of executing SQL.

Runtime dependencies, baseline inventory format, report schema and exit policies
are unchanged. The package release does not move the Marketplace `v1` Action tag;
its package `version` input is a separate pin.
