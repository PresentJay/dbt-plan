# dbt-plan v0.18.4 — accept dbt 1.12 snapshot directories

Projects containing ordinary models and snapshots compiled by dbt 1.12 can now
create a baseline. Previously, `dbt-plan snapshot` stopped with exit 3 because the
compiler stores snapshot SQL under a directory named after its source SQL file:

```text
snapshots/book_history.sql/book_history.sql
snapshots/book_history.sql/publisher_history.sql
```

The directory is traversed and every SQL file is inventoried. An empty SQL-named
directory, a symlink/junction, a special file, or changed baseline paths/bytes
still fails integrity checks. Snapshot definition changes remain review-required
warnings; snapshot DDL execution is not predicted.

## Upgrade

```bash
pip install --upgrade dbt-plan==0.18.4
# Optional MCP server:
pip install --upgrade 'dbt-plan[mcp]==0.18.4'
```

A separate dbt 1.12 checksum change can still produce `stale_source` warnings
for unchanged SQL snapshots ([#314](https://github.com/PresentJay/dbt-plan/issues/314)).
Those warnings remain: accepting the normalized checksum alone would miss
meaningful whitespace edits inside SQL literals or after line comments.

Inventory format, JSON fields, and CLI exit policies are unchanged. The package
release does not move the Marketplace `v1` Action tag; the Action reference and
its `version` package input are separate pins.

The failure was reproduced with dbt Core 1.12.4 and dbt-duckdb 1.11.0 in the public
[dlt-dbt-duckdb-evidence project](https://github.com/Ddscully/dlt-dbt-duckdb-evidence).
This is compatibility evidence from a local fixture run, not an accepted
integration or a warehouse execution-safety guarantee.
