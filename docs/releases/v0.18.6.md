# dbt-plan v0.18.6 — preserve downstream risk through SQL query scopes

This patch fixes a false-safe found while testing dbt-plan against a public
DuckDB project. Renaming an upstream view column could leave a downstream CTE
reading its old name while the report still exited 0. A fresh compile reproduced
the failure; neither partial parsing nor a UTF-8 BOM caused it.

The reference reader now resolves physical table aliases within each SQL query
scope. Reusing an alias in a nested query no longer hides the outer read. When a
named CTE, derived-table or correlated read cannot be attributed to a physical
source, the reader refuses to establish an empty read and keeps the existing
conservative risk/refusal path. Pure stars still do not count as explicitly named
reads; inherited column loss is checked separately.

This can introduce review warnings for derived reads that the tool cannot prove.
It does not add full SQL lineage or claim that every such read will fail at
runtime. See [#321](https://github.com/PresentJay/dbt-plan/issues/321).

## Upgrade

```bash
pip install --upgrade dbt-plan==0.18.6
# Optional MCP server:
pip install --upgrade 'dbt-plan[mcp]==0.18.6'
```

Pin the Action's Python package separately with `version: '0.18.6'`. The package
release does not move the Marketplace `v1` Action tag. The report schema, snapshot
inventory, exit policies and runtime dependencies are unchanged.

## Validation boundary

The regressions cover CTE/derived reads, nested alias reuse, pure stars and CLI
reports with and without a BOM. A local replay of the original public-project
control now reports the removed `customer_region` column and the downstream
broken reference with exit 1, instead of safe/exit 0. The temporary source change
was restored. This is local compatibility evidence, not an accepted integration
or confirmed adoption.

The repository sample runner also stops on CLI execution errors while continuing
to display completed findings. Its subprocess regressions cover codes 0/1/2,
3/127 and failures in later output calls. The runner lives in the repository and
is not included in the Python package artifacts.
