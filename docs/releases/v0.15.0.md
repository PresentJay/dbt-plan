# dbt-plan v0.15.0 — safer verdicts and smoother contributions

## Highlights

- Use custom target directories with `run`, the GitHub Action, and MCP.
- Get an explicit warning when a baseline cannot be read, and avoid false safe
  MCP verdicts when analysis refusals remain.
- Pipe `run --format json` into other tools without snapshot progress corrupting stdout.
- Catch deleted models even when old compiled files remain, and detect broken
  references through downstream `SELECT *` chains and aliased relations.
- Read shorter data-test names in human output while retaining full names in JSON.

## Contributor experience

PRs to dbt-plan now get an automatically updated CI status comment with failure
links. Authors can use `/ci` to refresh status and `/ci retry` for transient
failures. External code still needs maintainer execution approval.
See [the contribution guide](https://github.com/PresentJay/dbt-plan/blob/main/CONTRIBUTING.md#checking-ci-on-your-pull-request).

## Upgrade notes

Some cases that previously exited successfully now warn because analysis could
not establish safety. Review the warning rather than treating it as a regression.
Existing generated workflows must be regenerated to pick up the removal of path
filters. The contributor status bot is specific to this repository; it is not
installed into consumer projects.

```bash
pip install --upgrade dbt-plan==0.15.0
```
